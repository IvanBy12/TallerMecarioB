# S4-B02 integrity fixtures

Canonical tiny, synthetic fixtures; no customer content or secrets. Normal CI only reads these files; it needs no encoder or network.

- `pixel.png`: 1×1 opaque red, PNG IHDR/IDAT/IEND produced with Python standard-library zlib and CRC32.
- `pixel.jpg`: PNG converted by macOS `sips` (JPEG).
- `pixel.webp`: 2×2 red image generated by Pillow's WebP encoder.
- `clip.mp4` / `clip.mov`: three 32×32 white H.264 frames at 3 fps, encoded with macOS AVAssetWriter, respective MP4 / QuickTime containers. No audio or PII. They test actual containers independently of duration policy and B04 binding.
- A minimal one-page PDF with a real catalog/page tree and classic xref is generated in `../fixtures.cjs`.

Operational sessions in the API suite are inserted only by a clearly marked privileged fixture helper. They do not certify the public operational upload path, which remains blocked by S4-B04.
- `fragmented.mp4` / `fragmented.mov`: the three real H.264 samples from `clip.*`, repackaged into an ISO-BMFF init segment with empty sample tables, `mvex/trex`, one `moof/traf/tfhd/tfdt/trun` and `mdat`. The sample run carries explicit durations/sizes and a moof-relative byte offset. Independently decoded with macOS AVFoundation (three frames each); CI needs no decoder. Byte-offset corruption is tested separately.
- `fixtures.cjs` also generates valid one-frame APNG and uncompressed/Flate-compressed PDF xref streams with a real catalog/page tree. APNG is intentionally terminal unsupported; its public response does not claim corruption.
